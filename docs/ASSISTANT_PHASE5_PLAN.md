## 2. Current authority and Graph contract

Actual mail/calendar operations require a freshly loaded active internal profile, enabled global/user assistant settings, a live unrevoked unexpired BDR assistant grant, applicable role/module gates and operation-specific authorization. Missing or malformed authority fails closed. Recheck before dispatch and every paginated read. A cached application token is a service credential, never a cached authorization decision. Token material stays server-side and out of logs, planner context and frontend responses. Human configuration metadata can be read before the first assistant grant; it does not establish Graph access.

Normal read scope is exactly `{normalize(live profiles.email)} | normalize(live profiles.rfp_mailboxes) | normalize(SHARED_MAILBOXES)`, finite for every role including Executive and IT Admin. Only authorized user administration changes mailbox mappings. Normal tools do not inherit PM full-view scope, accept arbitrary resource paths or enumerate application-wide mailboxes. Malformed, unknown and out-of-scope targets have one public refusal before Graph. There is no MS_SENDER or alternate-mailbox fallback.

app/services/assistant_ms.py validates current BDR authority before acquiring the existing app credential. assistant_graph.py provides bounded fixed-origin HTTPS transport with no redirects, environment proxies or retries. Adapters construct encoded `/users/{mailbox}/...` paths, bound query options and fence continuation URLs to the original mailbox and operation. App reach may still exceed BDR scope; the application never presents that reach as user authorization.

## 3. Normal reads, staging and retention

email_search, email_read and email_attachment_to_staging have assistant-only routes under `/assistant/mail` and declared mail ToolSpecs. Searches default to 30 days, cap at 90 days and 50 results, with bounded pagination. Human-authored fields are tainted. Full bodies and attachment text are stored out of line with 30-day expiry for ordinary mail and 7-day expiry for review. Transcript blocks and history replay contain bounded metadata/summaries, not a second indefinite raw-body copy. Legal hold suspends content purges.

Attachment staging rechecks parent mailbox/message access and owner scope, accepts validated PDF content under the existing staging limits plus the mail adapter's 20 MB cap, and rejects reference attachments, arbitrary remote URLs and caller-selected storage paths. Preview is a human-only owner-bound `GET /assistant/files/{file_id}/preview`, returning a fresh 60-second signed PDF link after ownership/expiry checks. The UI fetches it without credentials, forces a PDF blob MIME, and uses the existing PDF preview modal; email HTML and remote images are never rendered.

## 4. Approved sends

email_draft creates the immutable external_send approval; `/assistant/mail/send` executes only under its approval continuation. The normalized live primary profiles.email is the sender and Reply-To, using application-authenticated `/users/{sender}/sendMail` with saveToSentItems=true. No model-controlled sender, alias/shared sender, `/me`, historical OAuth identity or MS_SENDER fallback. Sender and authority are frozen as preconditions, then rechecked before dispatch; a remap invalidates the card.

Recipients resolve from authorized current internal/profile/contact records or exact address tokens in the current/immediately previous user's own text, excluding recognizable quotes/forwards/HTML/code. No Bcc or model-supplied headers/Reply-To. Typed-text heuristics cannot distinguish every unmarked paste. Hrefs require exact typed provenance or a server-issued BDR artifact. The frozen preview shows sender, To/Cc with internal roles, Reply-To, subject/body, href/anchor pairs, attachment metadata/PDF previews and all three send markers. The frontend renders escaped text, keeps destinations inert, and disables email approval when required preview data is absent.

Conservative disclosure policy: a tainted source conversation, any attachment, or detected bid amounts restricts every recipient to active internal ACTUAL_BID_VIEWER_ROLES. This is intentionally stricter than the earlier design's bid-pattern-only restriction, because free text and attachments cannot be reliably classified as free of actual bid amounts. Ordinary untainted attachment-free messages without detected bid amounts may still go to bound external contacts. Execution revalidates the same policy.

The server appends the visible approved-user footer, opaque X-BDR-Assistant UUID and Sent Items category `Sent by assistant`. Small attachments are inline below 3 MB total; larger approved PDFs use frozen short-lived BDR links whose expiry is rechecked before dispatch. Existing test-bench routing remains in force. email_log records human sender, effective recipients and assistant run/approval/send provenance.

A database transaction claims one approval/attempt and its 20-per-user Pacific-day quota after live authority/sender checks. Graph 202 means accepted, not delivered. Timeout/process death after a claim is uncertain and never automatically retried; replay returns the prior attempt. Already dispatched HTTP can finish after revocation, but a later unclaimed dispatch must fail its fresh authority gate. The UI distinguishes accepted, uncertain and refused outcomes, including result.summary.outcome.

## 5. Executive mailbox review and audit

read_mailbox remains a separate sensitive_read operation under `/assistant/mail/review`, using the same app credential and a distinct authorization path. Executive/IT Admin only, explicit immutable server-backed mailbox_review conversation, target/window approval and human reason of 10 to 500 characters. Dispatch rechecks role, grant, exclusions, mode and the database limits of 3 distinct targets per run and 10 accesses per reader per Pacific day. Audit metadata and immutable human reason are committed before content release; outcome events are separate. An audit failure releases no sensitive result.

Review uses tool-less assistant_extract before exposing body-derived information to the planner. Extraction failure has no raw-body fallback. Review excludes normal mail operations, writes/sends/expensive actions, memory, scheduling, browser and web tools at discovery and runtime. Missing mode provenance fails closed. Mailbox taint is permanent. A fresh normal conversation copies neither review text nor summaries; the UI clears the composer and suppresses attachments/incognito while reviewing.

MAILBOX_EXCLUSIONS is enforced by BDR, not an asserted Exchange tag. Exclusion changes are audited. First-target-per-Pacific-week notices, exclusion-change notices and count-only weekly digests go through atomically deduplicated assistant inbox plus bell delivery to all active Executive and IT Admin reviewers. There is no separately configured reviewing-owner recipient, no automatic digest email and no unattended model call. Broad reviewer delivery is the current deviation from the earlier single-owner notice proposal.

Human IT Admin log endpoints `/assistant/mailbox-access` and `/assistant/evidence-access` expose bounded cursor-paginated metadata; the mailbox log includes read-only exclusions. Executives receive review notices/digests, but gain no other-user conversation inspection. Human-only POST `/assistant/inspection/conversations/{id}/read` and `/export` require owner_id, reason_kind support/legal/offboarding/other and a 10-to-500-character reason. The audited RPC excludes raw tool results and mailbox-tainted content unless the purpose is legal. Owner GET `/assistant/conversations/{id}/views` exposes viewer/action/date metadata only, used by the conversation notice banner. Every read/export is audited; export responses are no-store JSON attachments.

## 6. Calendar, web and frontend contracts

Calendar preferences are human GET/PATCH `/assistant/calendar/preferences`: `{available,enabled,mode:'context'|'all',lead_minutes,unavailable_reason}`; PATCH accepts enabled/mode/lead_minutes. Opt-in defaults to context mode, lead 15 minutes bounded 5 to 180, poll interval 10 minutes and horizon 3 hours. Enabling performs a bounded calendarView capability check using the existing app; 401/403 keeps/disables reminders. A configured status is not a claim that Microsoft confirmed the permission. Mail permission never implies calendar permission.

Calendar wire times deliberately use Graph's UTC default, with no Pacific Standard Time Prefer header. UTC/offset timestamps make repeated DST hours unambiguous; unexpected offset-free non-UTC values are rejected. Pacific remains the business timezone for quotas/notices and display, not ambiguous wire-time reconstruction. Context mode deterministically matches invite addresses to authorized GC/project contacts on active bidding projects whose internal due instant is in the next seven days. This rolling lookahead is broader than the original calendar-week wording. Canceled/all-day/private/confidential events are skipped; no event body/title/attendee dump persists in unattended reminders. Durable claims deduplicate reminders and atomically insert inbox/bell notices. No calendar writes, unattended model calls or mail sends.

The vetted web gateway adapter is implemented, but no provider is configured by this build. See [ASSISTANT_WEB_GATEWAY.md](ASSISTANT_WEB_GATEWAY.md) for the exact authenticated `/search` and `/fetch` gateway JSON contract and `public-https-no-redirects-v1` policy. ASSISTANT_WEB_ENABLED, ASSISTANT_WEB_API_URL and ASSISTANT_WEB_API_KEY gate it. The gateway must enforce public destination IP pinning and reject redirects; its attestation does not replace provider review. The adapter independently checks typed provenance, safe HTTPS/DNS, bounded output and contradictory attestations. Search queries must come from current/previous unquoted user text; search results grant no fetch authority. Results are cited and tainted. There is no direct arbitrary-fetch fallback.

Human GET `/assistant/outlook` returns `{available,authentication:'application',mailbox,shared_mailboxes}`. The settings card describes organization-managed scope and no sign-in requirement; it never calls a probe or offers connect/disconnect. POST `/assistant/conversations` accepts mode normal/mailbox_review, with elevated role checks for review, and responses round-trip mode plus mailbox_tainted_at. Frontend UI includes review/fresh-normal controls, safe email/PDF previews, calendar preferences/status, IT Admin access logs and owner audit notices. No OAuth route, callback query, cookie or Microsoft credential is used.

### Exact persistence and RPC contract

`assistant_ms_connections` is a persistent per-user generation tombstone. Fields: user_id UUID PK, generation bigint, status disconnected/connecting/connected/revoked, tenant_id/object_id/home_account_id/upn/match_basis/matched_address, scopes text[], cache_ciphertext/cache_nonce/cache_key_id text (ciphertext and nonce use the existing vault hexadecimal bytea representation), cache_version bigint, token_expires_at, refresh_claim_id UUID, refresh_claim_until, shared_mailboxes_reachable text[], connected_at, revoked_at, revoked_reason, last_error_code, created_at, updated_at. Never delete a connection on disconnect and recreate generation zero.

`assistant_ms_oauth_states` fields: state_hash text PK (SHA256 hex), browser_hash text, user_id UUID, generation bigint, encrypted flow fields flow_ciphertext/flow_nonce/flow_key_id, expires_at, consumed_at, completion_id UUID, completed_at, created_at. Index user_id/generation and expires_at. State TTL 10 minutes; refresh lease 60 seconds. Expired/completed flow secrets are cleared promptly and purged within 24 hours. Legal hold never requires keeping usable OAuth secrets.

All RPC names and parameters below are exact. SQL argument names have `p_` prefixes. Every return is a jsonb object, `{ok:false,code:<fixed code>}` on predicate failure. Success is `{ok:true}` plus specified fields. Generation/cache_version are bigint. All functions SECURITY INVOKER with pinned search_path, service_role EXECUTE only, PUBLIC/anon/authenticated explicitly revoked. Tables force RLS with no client policies. Lock eligibility rows first (profile, global settings, assistant profile, delegation), then connection, then state consistently; never hold locks across provider HTTP. Revocation only locks connection/state. Eligibility means current active internal profile, enabled global assistant settings, enabled assistant profile (missing profile defaults enabled), and live unexpired assistant delegation; identity checks use the current original email/rfp_mailbox binding. Database clock governs expiry.

- `assistant_ms_begin(user_id,state_hash,browser_hash,flow_ciphertext,flow_nonce,flow_key_id)`: require eligibility, lock/create connection, increment generation, clear old cache and claims, set connecting, invalidate old flows, insert new flow. Returns generation,expires_at. Starting reconnect intentionally disconnects the old identity immediately.
- `assistant_ms_consume(user_id,state_hash,browser_hash,completion_id)`: atomically require unexpired/unconsumed owner+browser-bound flow at current connecting generation and eligibility, mark consumed once and clear persisted flow ciphertext after capturing its return value. Returns user_id,generation,flow_ciphertext,flow_nonce,flow_key_id. Parent's state owner is HMAC-verified before the owner-scoped repo call. No cookie/bearer can retarget owner.
- `assistant_ms_complete(user_id,generation,state_hash,completion_id,identity,cache_ciphertext,cache_nonce,cache_key_id,token_expires_at,scopes,shared_mailboxes_reachable)`: require matching current connecting generation, consumed owner flow/completion id, not completed, original flow unexpired, eligibility and exact live binding. Store connected identity/cache, increment cache_version, clear flow secret and record completion. Returns generation,cache_version. Identity keys are tenant_id,object_id,home_account_id,upn,match_basis,matched_address.
- `assistant_ms_refresh_claim(user_id,generation,claim_id)`: require connected/current generation/live identity and no unexpired lease, claim 60 seconds. Returns generation,cache_version,cache_ciphertext,cache_nonce,cache_key_id,identity. Busy returns no secret.
- `assistant_ms_refresh_commit(user_id,generation,claim_id,expected_cache_version,cache_ciphertext,cache_nonce,cache_key_id,token_expires_at)`: require matching connected generation, unexpired claim, cache_version and live identity. Store encrypted rotated cache, increment version, clear lease. Returns generation,cache_version. An expired lease fails even without a replacement claimant.
- `assistant_ms_refresh_release(user_id,generation,claim_id,error_code)`: clear only matching claim, write allowlisted error code; return ok. No credential overwrite.
- `assistant_ms_revoke(user_id,reason,expected_generation=null)`: lock/create tombstone; optional generation mismatch returns stale. Otherwise increment generation and cache_version, clear credentials/claims and all pending flow secrets, mark revoked. Returns generation. Human disconnect/remap/offboard omit expected_generation; invalid_grant workers supply captured generation so stale failure cannot revoke a new connection.

### Service and browser contract

Root's `assistant_ms_crypto` uses the existing browser-agent keyring and AES-GCM rotation primitives, with distinct AAD `assistant-ms|purpose|user_id|binding-id`: flow binding is state_hash, cache binding is generation. The state contains HMAC-authenticated owner UUID plus random entropy; a separate browser nonce goes in a secure HttpOnly SameSite=Lax 10-minute cookie and only its hash goes in the state row. Callback consumes state and verifies browser binding before redemption. It is a public fixed callback, not a bearer-authenticated management endpoint. Never put code/state/provider text in application or proxy access logs; callback route logging must redact query strings.

MSAL validates auth-code-flow nonce/issuer, then service requires configured tenant, selected account/home_account_id, `/me.id == oid`, and UPN/live profile match. Persist encrypted serializable MSAL cache, not an assumed raw refresh-token field. Refresh rechecks `/me` object/UPN plus original live binding. Provider-denied callbacks consume their state and return a fixed error. Deactivation, remap, disconnect and newer start all fence out an older callback. No process-global token cache. Re-read current generation/live authority immediately before Graph use; already dispatched HTTP cannot be recalled and no stronger promise is made.

Human endpoints: GET `/assistant/outlook` returns `{available,connected,upn,shared_mailboxes_reachable,revoked_reason}`; POST `/assistant/outlook/connect` returns `{authorization_url}` and sets browser cookie; POST `/assistant/outlook/disconnect` returns sanitized status and clears cookie. Callback redirects only to `/settings/assistant?outlook=connected|failed`; query is a hint to reread backend status. Frontend allows only configured commercial-tenant login.microsoftonline.com authorization URLs. No user return_to or token-bearing frontend response. New config: assistant_outlook_enabled=false, assistant_ms_tenant_id/client_id/client_secret/redirect_url. Status/disconnect remain available to eligible human owners when integration unavailable; start requires configured enabled integration. Model spending caps do not gate connection management.

## 9. OAuth implementation and verification, 2026-10-26

Migration 0182 includes 11 invoker functions. Connections and state tables have forced RLS, no client policies, and no anon/authenticated access. Only service_role can execute lifecycle RPCs. The profiles BEFORE UPDATE trigger fences any existing connection when email, mailbox mapping, role or active status changes, in the same transaction as the edit. The nightly purge deletes at most 500 expired states with SKIP LOCKED; connection generation tombstones survive disconnect. The retention sweep requires the existing scheduler and maintenance flags.

The public callback uses signed state plus an HttpOnly browser cookie, rejects duplicate/unexpected parameters and always redirects to a fixed settings URL without provider errors. Uvicorn callback query logging is redacted. MSAL cache-event logging is suppressed because its normal DEBUG masking omits authorization code and PKCE fields. Reverse-proxy logs must independently redact callback queries. Credential refresh verifies the persisted MSAL account and live /me identity even when a cached token result omits id_token_claims. New users can query status before creating an assistant delegation; actual authorization and token use still require it.

Critical revocation executes before MFA factor removal, independently of feature flags. Offboarding has a critical microsoft step; hard deletion refuses if it fails. Database profile-change fencing covers remaps and deactivations even while the app integration is disabled.

`scripts/check_assistant_outlook.sql` ran successfully against dev BDR (bpidntbyvoooqvaispup). It checks browser binding, callback and completion replay, live profile remap, duplicate refresh claim, cache-version fencing, disconnect/old-callback ordering, stale invalid_grant, expired delegation, cleanup and client grants, then rolls everything back. Post-check: zero connections and zero OAuth states. These are real SQL sequential-interleaving assertions, not a simultaneous two-connection race test. Such concurrency testing and real Entra callback/refresh acceptance remain activation gates.
